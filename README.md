### 두 가지 판 (2026-11-12)

| | 실제 작동판 (`live`) | 시연판 (`demo`) |
|---|---|---|
| 용도 | 실제 제출용. 차량·내비·음성 신호로만 움직인다 | 발표·심사용. 짧은 시간에 전체 흐름을 보여 준다 |
| 오른쪽 위 | **설정**: 같이하기 기본값 · 기록 · SDK 진단 | **시연 도구**: 시연 배속, 시각, 대답 버튼, 주차/주행·동승자 지정, 워치·캘린더 시연값, 가상 주행 + 기록 · SDK 진단 |
| adb 시연 명령 | 받지 않음 | 디버그 빌드에서만 받음 |
| 빌드 | `./gradlew assembleLiveRelease` | `./gradlew assembleDemoRelease` |

판은 Gradle `productFlavors`(`app/build.gradle.kts`)로 나뉘고, 코드에서는 `BuildConfig.DEMO_TOOLS`로 구분한다. 핵심 로직(`core/`)은 두 판이 같다.

### 바로 실행하기
1. Pleos Connect Emulator 2.1.0을 켠다(설치는 아래 [3. 빌드와 실행](#3-빌드와-실행)).
2. APK 설치:
   ```bash
   adb install -r PitStop_Shimpyo_release.apk   # Releases에서 받은 실제 작동판 APK
   ```
3. 앱 목록에서 **쉼표**를 연다 → **운행 시작**(실제 작동판은 앱이 켜져 있고 차량 신호가 연결돼 있으면 P단을 풀 때 저절로 시작하고, 20분 넘게 주차하면 저절로 끝난다).
4. 짧게 보려면 오른쪽 위 **시연 도구** → **시연 배속**(1초 = 1분)을 켜고 [4. 2차 PT 시연 순서](#4-2차-pt-시연-순서-약-5분)를 따라 한다.
   차량 상태(기어 P/D, 동승석 착좌)는 Pleos **Virtual Console**에서 바꾸거나 시연 도구의 같은 버튼으로 바꾼다.

소스에서 빌드: `./gradlew installDemoDebug`(시연판) · `./gradlew installLiveDebug`(실제 작동판) · 단위 테스트: `./gradlew testLiveDebugUnitTest` (6차 점검 159개 통과, 2026-11-14, 무작위 상황 시험 포함)

### 웹 시연판 (설치 없이 브라우저에서)
[`web/shimpyo.html`](web/shimpyo.html) 파일 하나를 크롬이나 엣지로 열면 된다(파일을 더블클릭). 에뮬레이터 없이 같은 흐름을 보여 준다.
- 출발 인사·수면 점검·워치 수면 기록 → 위험도 계산(앱과 같은 기준) → 말놀이 10종·같이하기(차례·팀 점수·동승자 패드) → 졸음쉼터 제안(공공데이터 253곳) → 경유지·도로 경로 지도 → 주차 → 낮잠 캡슐(빛으로 깨우기) → 재출발
- 왼쪽 ‘가상 차량’이 공조·시트·무드등·창문 변화를 보여 준다(앱에서는 Pleos Vehicle SDK로 실제 제어).
- 소리: 브라우저 음성으로 읽어 준다. 마이크: 시연 도구 ‘마이크로 대답’을 켜면 크롬·엣지 음성 인식으로 말해서 답한다(인터넷 필요, 마이크 권한 허용).
- 지도: 오픈스트리트맵, 도로 경로는 OSRM(둘 다 인터넷 필요, 키 필요 없음).
- 시연 도구는 앱과 같다(시연 배속, 말놀이 바로 하기, 정답 말하기, 수면 점검 대답, 주차/주행, 동승자, 워치 수면, 캘린더, 가상 주행) + 질문마다 자동 대답.

### 시연 도구로 할 수 있는 것
- **말놀이 바로 하기**: 끝말잇기·초성 퀴즈·O/X·단어 기억하기·숫자 거꾸로·넌센스·숫자 계산·구구단·지역 O/X·쉼터 거리 맞히기 중 하나를 골라 위험도와 상관없이 바로 시작한다. 운행 전이면 인사·수면 점검을 건너뛰고 놀이부터 한다(지역 O/X·쉼터 거리 맞히기는 현재 위치가 있어야 한다).
- **운전자 대답·수면 점검 대답**: 언제 눌러도 된다. 쉼표가 질문을 말하는 중이면 받아 두었다가 질문이 끝나자마자 넣는다(버튼 위에 ‘받아 둔 대답’이 보인다). **정답 말하기**는 지금 문제의 정답을 넣는다(수면 점검은 7시간·아침 7시·졸림 3).
- **마이크로 직접 대답**: 에뮬레이터를 `-allow-host-audio`로 켜면 PC 마이크로 말해서 대답할 수 있다(아래 ‘실행’ 참고).

녹화할 때는 화면을 가리지 않도록 adb로도 넣는다(디버그 빌드만):
```bash
adb shell am start -n com.pitstop.shimpyo.demo/com.pitstop.shimpyo.MainActivity --es demo correct
```
`demo` 값: `start`·`end`(운행 시작·종료) · `park`·`drive`(주차·주행) · `seat_alone`·`seat_passenger`(동승자) · `drive_sim`(쉼터 쪽 가상 주행) · `hour:2`(시각) · `correct`(정답) · `yes` · `no` · `together` · `solo` · `slow` · `speed_on`/`speed_off`(시연 배속) · `auto_on`/`auto_off`(질문마다 1.5초 뒤 자동 대답) · `game:CHOSUNG`처럼 `game:` + `WORD_CHAIN`·`CHOSUNG`·`OX`·`MEMORY`·`REVERSE_DIGITS`·`NONSENSE`·`ARITHMETIC`·`GUGUDAN`·`REGION`·`DISTANCE`(말놀이 바로 시작)

### 0.2.1 6차 점검 (2026-11-14)
- 원본 138개 테스트 통과와 두 릴리스 빌드를 먼저 확인했다. 수정 후 전체 159개 테스트와 웹 안전 회귀 6개를 통과했다.
- 주차 신호 오류·소실을 이전 P단 값으로 보지 않는다. 기어 지원 차량은 기어 값을 잃으면 주차 브레이크로 대신하지 않는다.
- 휴식·깨우기 중 주차 확인을 잃으면 휴식을 중단하고 복귀한다. 시트·창문이 완료 응답 전에 움직였거나 일부 이동 뒤 실패할 가능성도 반영했다.
- 공통 차량 복귀도 실패·응답 누락 때 원래 값과 영역을 보존하고, 원래 값을 모르면 완료라고 하지 않는다.
- 시트 이동은 시간 초과·취소 시 정지를 요청하고, 늦은 응답으로 다시 움직이지 않는다. 목표 도달과 정지 응답을 확인해야 성공이다. 복귀 실패 때는 원래 위치를 보존한다.
- 실제 작동판의 가상 내비는 경유지 추가 성공을 꾸며 내지 않는다. 내비 SDK 호출은 실제 경로 반영 확인과 다르므로 음성·화면도 ‘추가 요청’으로 안내한다.
- 웹도 주차 확인·취소 이후 늦은 제어·내비 연결 실패 규칙과 안내를 맞췄다. 기존 시트 이동 코드를 시험 가능한 파일로 옮기고 남은 미사용 상수·import를 제거했다.
- 상세 결과·재현 방법·미확인 항목: [6차 검증 보고서](docs/review/REVIEW_6.md). APK 빌드 성공은 실제 차량 안전성 검증을 뜻하지 않는다.

### 0.2.1 리뷰 반영 (2026-11-12)
코드 리뷰에서 찾은 오류를 고쳤다. 고친 동작은 `VoiceParsingReviewTest`·`ReviewFixesTest`와 `ControllerFlowTest`의 새 항목으로 묶었다(1차 112개, 2차 123개, 3차 점검 뒤 126개).
- **안전**
  - 주차 판정을 P단 기준으로 바꿨다. 예전에는 D단에서 주차 브레이크만 걸어도 주차로 봐서, 쉼터로 가는 중 정체에서 등받이가 눕혀질 수 있었다(`core/ParkingSignal.kt`).
  - 쉼터가 아닌 곳에서 P단을 넣으면 “여기서 15분 쉬어 갈까요?”라고 먼저 묻는다(한 번 주차에 한 번).
  - 휴식 중 출발하면 등받이를 바로 세운다(예전에는 다시 주차할 때까지 누운 채로 달렸다). 눕히기·창문 열기만 주차 중에 한다.
- **말 알아듣기**
  - “괜찮아, 쉬었다 가자”, “그만 가고 쉬자”, “나중에 말고 지금 쉬자”, “안 쉬면 안 되겠다”, “네 좋아요 괜찮아요”를 거절로 읽던 문제. 쉬자는 말을 먼저 본다.
  - “응?”, “어? 뭐라고?” 같은 되묻기를 ‘예’로 읽던 문제. 이제 다시 묻는다.
  - 수면 시간 “한 세/네/서너 시간”을 1시간으로 읽던 문제(어림말 처리, 범위는 낮은 쪽). “잘 못 잤어”는 0시간이 아니라 모르는 대답으로 본다.
  - 기상 시각 “정오”를 5시로, “1시간 전에”를 1시로 읽던 문제. “방금”, “30분 전”도 읽는다.
  - O/X: “안 맞아”→O, “틀린 말 아니야”→X, “엑스 아니고 오”→X, “no”→O로 읽던 문제.
  - 같이하기: “혼자 하기 싫어”를 ‘혼자’로 읽고 “같이 하지 말자”를 못 알아듣던 문제.
- **동작**
  - 실제 작동판은 P단을 풀고 출발하면 운행을 저절로 시작한다(`ShimpyoConfig.autoStartOnDrive`, 시연판은 끔).
  - 마이크가 없어 쉼터 제안의 대답을 못 들으면 거절로 세던 문제. 이제 알리고 나중에 다시 권한다.
  - 실제 작동판이 차량 서비스를 못 찾으면 시뮬레이터가 제어 ‘완료’를 꾸며 내던 문제. 이제 ‘지원 안 함’으로 답하고 화면에 “차량·내비 연결 안 됨”을 띄운다.
  - 쉼터를 고를 때 최근에 지난 쉼터의 노선(지금 달리는 고속도로)을 먼저 본다. 분기점 근처에서 옆 고속도로 쉼터를 고르지 않게. 제안 문장은 “직선으로 약 ○킬로미터 앞에”라고 말한다.
  - 차량 주행 시간 값의 단위(분·초)와 시동을 껐다 켤 때의 되감김을 확인한 뒤 쓴다(`core/VehicleTripTime.kt`). 실차 검증 전이라 값을 그대로 믿지 않는다.
  - 대답 속도 기준값을 대답 종류(바로 답하는 질문·생각해야 하는 문제)마다 따로 둔다. 계산 문제가 원래 느린 것이 졸음처럼 보이지 않게.
  - KSS 척도 설명(약 12초)은 운행마다 처음 한 번만 하고, 그다음은 짧게 묻는다.
- **문구·문서**
  - 재출발 멘트의 “원래 목적지로 안내할게요”는 쉼표가 하지 않는 일이라 “쉼터 경유지는 지웠어요. 목적지가 있으면 내비가 이어서 안내해요.”로 바꿨다. 커피 권유는 “원하시면”으로.
  - README의 없는 파일 링크(`apk/…`, `docs/demo/shimpyo_app_demo_0.2.0.mp4`)를 실제 위치로 고쳤다. 쓰지 않던 `restPausedForDriving`을 지웠다.
  - 웹 시연판(`web/shimpyo.html`)에도 말 알아듣기·문구·대답 속도 기준 변경을 똑같이 반영했다.
- **2차 점검에서 추가로 고친 것**(`ShelterSideTest`·`SecondReviewTest`·`SecondReviewControllerTest`)
  - **반대 차로 쉼터**: 졸음쉼터 253곳 중 81곳은 한쪽 차로에만 있다. 예전에는 방향을 보지 않아, 예컨대 중부선 오창에서 북쪽(하남 방향)으로 가면 바로 앞의 농다리(남쪽 방향 차로에만 있음)를 경유지로 넣어 다음 나들목에서 돌아오게 만들었다. 이제 쉼터 짝(상·하행) 사이를 지날 때 오른쪽 쉼터의 ‘도로노선방향’으로 달리는 방향을 알아 두고, 같은 노선에서 방향이 정반대인 쉼터는 고르지 않는다(위 예에서는 진천). 방향을 아직 모르면 한쪽에만 있는 쉼터 대신 10km 안쪽으로 더 가서 있는 양쪽 쉼터를 먼저 고른다. 원본 데이터의 방향 오타(양앙·회턱·양기점)는 비교할 때 바로잡는다. 미니맵·거리 맞히기에도 같은 규칙을 쓴다.
  - **“쉬고 싶어”를 알아듣지 못하던 문제**: 쉼표는 “졸리면 언제든 ‘쉬고 싶어’라고 말해 주세요”라고 안내했지만, 실제로는 질문한 뒤에만 듣고 말놀이 대답 속의 “쉬고 싶어”는 놀이 답으로 채점했다. 이제 어느 질문의 대답이든 쉬자는 말이면 놀이를 멈추고 다시 묻지 않고 쉼터를 경유지로 넣는다(서 있으면 바로 휴식). 안내 문구도 사실대로 “졸리면 화면의 ‘지금 쉬기’를 누르거나, 제가 말을 걸 때 ‘쉬고 싶어’라고 해 주세요.”로 바꿨다(늘 듣고 있지는 않으므로).
  - 계산·구구단에서 문제를 되풀이하며 답하면(“7 곱하기 8은 56”) 앞의 7을 답으로 채점하던 문제.
  - 끝말잇기 안내의 조사 오류(“‘판’로 시작하는” → “‘판’으로 시작하는”).
  - 차량 주행 시간 단위를 정하는 동안 차가 서 있으면 ‘분 단위’로 잘못 정하던 문제(값이 늘 때까지 기다린다).
  - 쓰이지 않으면서 “출발 직후 기준값 측정에 쓴다”고 적혀 있던 `SmallTalkGame`을 지웠다. 말놀이 근거 문헌을 정확한 서지(Zhang 외 2025, Applied Ergonomics 129:104616; Large 외 2017)로 바꿨다.
  - **운전자의 경유지를 지울 수 있던 문제**: 휴식을 마치거나 안내를 접을 때 무조건 첫 번째 경유지(FIRST)를 지웠다. 쉼터에 이미 도착해 내비가 그 경유지를 지나간 뒤라면, 운전자가 원래 넣어 둔 다음 경유지가 지워질 수 있다. 이제 쉼표가 넣은 경유지에 도착한 뒤에는 지우지 않는다. 도착한 경유지를 Pleos 내비가 실제로 목록에서 빼는지는 SDK 문서로 확인되지 않아 에뮬레이터에서 확인해야 한다.
  - 웹 시연판에도 같은 규칙을 넣었다(쉼터 데이터에 방향 값 추가).
- **3차 점검에서 고친 것**(`ThirdReviewTest`)
  - 2차 때 넣은 안내 “졸리면 화면의 ‘지금 쉬기’를 누르거나…”가 ‘주행 중 화면 조작을 요구하지 않는다’는 안전 원칙과 어긋났다. “졸리면 제가 말을 걸 때 ‘쉬고 싶어’라고 해 주세요. 차를 세운 뒤에는 화면의 ‘지금 쉬기’를 눌러도 돼요.”로 바꿨다.
  - 깨우는 말이 주행 중에도 “창문을 잠깐 열어…”라고 했다(창문은 주차 중에만 연다). 이제 실제로 할 일만 말한다. 재출발 멘트의 “쉼터 경유지는 지웠어요”도 지웠다(도착한 경유지는 지우지 않고, 경유지 없이 쉰 경우도 있다).
  - 쉼터로 가는 동안은 내비가 앞에 나와 있어 마이크를 못 쓸 때가 많다. 그때 쉼터가 아닌 곳에서 P단을 넣으면 대답을 들을 수 없는 질문을 하던 것을, 차가 서 있으니 “쉼표 화면에서 ‘지금 쉬기’를 눌러 주세요”로 안내하게 했다. 쉼터 제안에 대답을 못 들었을 때의 말도 “마이크를 쓸 수 없어서”에서 “지금은 대답을 들을 수 없어요”로(앱이 뒤에 있을 때도 같은 상황이라서).
  - 화면·음성에 남아 있던 옛 주차 기준 문구(“주차 브레이크를 걸면 휴식을 시작해요”, “주차(P단·주차 브레이크) 중에만”)를 P단 기준으로 고쳤다.
  - 지도·경로 요청의 User-Agent가 “Shimpyo/0.1”로 고정돼 있던 것을 빌드 버전으로.
  - 웹 시연판에도 같은 문구 수정을 넣고, 헤드리스 크롬에서 운행 시작 → 말놀이 → 쉼터 제안 → 안내 → 주차 → 휴식까지, 그리고 말놀이 중 “그만하고 쉬자” → 바로 경유지까지 오류 없이 도는 것을 확인했다.
- **쉼터 데이터 좌표 보정**(`ShelterSideTest`): 원본 표준데이터에는 상·하행 두 행이 똑같은 좌표인 쉼터가 16곳(32행) 있어, 경유지를 넣어도 어느 차로인지 구분되지 않았다. 오픈스트리트맵 도로 기하(일방통행 차로와 진행 방향)로 각 행을 해당 방향 차로 바깥쪽에 다시 놓았다. 일광은 원본 좌표가 고속도로에서 1.2km 떨어져 있어 OSM의 일광졸음쉼터 위치로 바로잡았다. 방법과 한계는 `app/src/main/assets/README.txt`에 적었다. 웹 시연판 데이터도 같이 바꿨다. 같은 방법으로 148곳을 더 점검했고, 성남·적금 두 곳은 확인이 필요하다.
- **4차 점검에서 고친 것**(`FourthReviewTest`, `ShelterSideTest`) — 대부분 앞선 수정에서 새로 넣은 코드의 오류다.
  - 지난 운행에서 알아낸 ‘달리는 방향’을 새 운행에서도 썼다. 돌아오는 길이면 정반대라서 맞는 쪽 쉼터를 걸러 냈다. 운행을 시작할 때 지우고, 유효 시간도 주행 분이 아니라 시계로 잰다.
  - 방향 판단이 ‘짝의 두 쉼터가 내 진행선 양쪽에 있을 때’만 됐는데, 차는 길 한가운데가 아니라 한쪽 차로를 달리므로 실제로는 거의 판단되지 않았을 것이다. 둘 중 어느 쪽이 더 오른쪽인지로 바꾸고, 실제 데이터의 모든 짝으로 검사한다.
  - 차량 주행 시간을 단위 확인 전에도 써서, 값이 초 단위면 출발 3분 만에 ‘연속 주행 180분’이 될 수 있었다. 확인 전에는 쓰지 않는다.
  - 계산 문제의 대답 속도 기준을 잡는 동안 다른 종류 기준과 비교해 첫 두 문제가 ‘2.5배 느림’으로 잡혔다. 기준을 잡는 동안은 비교하지 않는다.
  - 자동 시작이 차량 서비스가 없는 기기에서는 앱을 켜자마자 운행을 시작했다(가상 차량이 처음부터 ‘주행’). 실제 차량 신호가 있을 때만 켠다.
  - 자동으로 시작한 운행이 끝나지 않아, 목적지에 세워 둔 시간까지 연속 주행으로 셌다. 감시 단계에서 20분 넘게 주차하면 운행을 마친다(수동 시작은 쉰 것으로 보고 다시 센다).
  - “쉬고 싶지 않아”, “쉬어가기 싫어”를 쉬자는 말로, “쉴 필요 없어”를 모르는 말로 읽었다. “일어난 지 세 시간 됐어”를 3시에 일어난 것으로 읽었다.
  - 쉼터 데이터: 나머지 221행을 모두 점검해, 고속도로에서 1km쯤 벗어나 있던 성남 1행·적금 2행을 OSM의 쉼터 위치로 고쳤다(`assets/README.txt`).
- **5차 점검에서 고친 것**(`FifthReviewTest`, `ControllerFuzzTest`)
  - **무작위 상황 시험 추가**: 주차·출발·도착·버튼·무응답·되묻기·늦게 오는 음성 콜백·동승자·워치·캘린더·배속을 무작위로 섞은 상황을 돌리며, 주행 중 등받이 눕힘·창문 열림, 단계에 갇힘, 운행 종료 뒤 차량 원복, 예외를 검사한다. 점검 때 1만 가지 상황을 돌렸고, 테스트 묶음에는 600가지가 매번 돈다.
  - 이 시험으로 찾은 안전 오류 두 가지: ① 깨우는 말을 하는 몇 초 사이에 출발하면 그 단계에는 출발 처리가 없어 누운 채 달렸다. ② 휴식 중 출발 → “등받이를 먼저 세울게요”를 말하는 사이에 ‘지금 쉬기’나 말놀이 시작이 끼어들면 말과 함께 등받이 세우기까지 취소됐다. 휴식·깨우기 어느 쪽에서 출발해도 같은 처리(`endRestByDriving`)를 하고, 어떤 경우든 주행 중 등받이가 눕혀져 있으면 바로 세우는 안전장치(`seatSafetyNet`)를 넣었다.
  - 쉼터가 아닌 곳에서 “여기서 쉬어 갈까요?”를 묻는 사이 단계가 바뀌면(내비 도착 알림 등) 붙잡아 둔 상태가 풀리지 않아 다음 판단이 영영 멈췄다.
  - 차량 주행 시간을 처음 쓸 수 있게 되는 순간 화면의 연속 주행이 앱 시계 값에서 그날 시동 이후 전체 값으로 한 번에 뛰었다. 이어지도록 기준점을 잡는다.
  - ‘20분 넘게 주차하면 운행 종료·쉰 것으로 봄’을 배속 시간으로 재서 시연 중 20초만 세워 둬도 적용됐다. 실제 시간으로 잰다.
  - 기어·주차 신호가 없어 자동 시작을 못 하는 차에서도 “출발하면 자동으로 시작해요”라고 표시했다.
  - 앱이 화면 뒤에 있을 때 자동 시작되면 안드로이드 12+ 제한으로 포그라운드 서비스를 못 켤 수 있다. 화면이 다시 보일 때(`MainActivity.onStart`) 운행 중이면 다시 켠다.
  - 웹 시연판: 휴식·깨우기 중 ‘주행’을 누르면 아무 반응이 없어 가상 차량이 누운 채 남던 것을 앱과 같은 출발 처리로 맞췄다.
- 남은 확인: 실차·Pleos 에뮬레이터에서 P단 판정, 출발 감지 자동 시작, 등받이 세우기 타이밍을 다시 녹화해 확인해야 한다(안드로이드·Pleos 부분은 이번에 기기에서 돌려 보지 못했다).

| ② 각성 | 출발 전 수면 점검 대답으로 그날의 응답 속도 기준값을 잡고, 위험도가 오르면 여덟 가지 말놀이(끝말잇기·초성 퀴즈·O/X 상식·단어 기억하기·숫자 거꾸로 말하기·넌센스·숫자 계산·구구단)를 번갈아 건다. 경고 단계에선 집중이 더 필요한 놀이를 먼저 고른다. 외기 유입·송풍 강화 | Gleo AI TTS·STT, Vehicle(HVAC) |
| ③ 유도 | 진행 방향 앞쪽, **우리 쪽 차로**의 가장 가까운 졸음쉼터를 찾아(반대 차로에만 있는 쉼터는 빼고) “응” 한마디에 경유지로 추가. 제안하는 동안과 쉼터로 가는 동안 계기 자리에 쉼터 미니맵이 뜬다 | NaviHelper |
| ④ 휴식(낮잠 캡슐) | 쉼터에서 주차(P단)가 확인되면(쉼터가 아닌 곳이면 “여기서 쉬어 갈까요?”라고 먼저 묻는다) 15분 ‘커피 낮잠’: 등받이 눕힘, 무드등 낮춤, 휴식 공조. 끝나기 3분 전부터 소리 없이 무드등 40→70→100%, 실내 20도로 깨운다 | Vehicle(Seat, Light, HVAC), AAOS |
| ⑤ 재출발 | 목소리로 알린 뒤 등받이를 세우고 창문을 잠깐 열어 환기, 조명·공조 원위치 요청, 쉼표 경유지 정리(이미 도착한 경유지는 삭제하지 않음) | Vehicle(Window 등), NaviHelper |

### 낮잠 캡슐 (구현됨, `core/NapCapsule.kt`)
- **커피 낮잠**: 카페인을 마시고 바로 15분 이하로 자면 깰 즈음 카페인이 돌기 시작해, 둘 중 하나만 할 때보다 졸음이 더 줄었다(Reyner & Horne 1997, Psychophysiology 34:721 — 운전 시뮬레이터, 카페인 150mg + 15분 이하 낮잠). 15분을 넘기면 깊은 잠에 들어 깬 직후 더 멍해질 수 있어(수면 관성) 휴식 시간은 늘리지 않는다.
- **빛으로 깨우기**: 끝나기 3분 전 새벽빛(무드등 40%) → 2분 전 아침빛(70%, 실내 20도) → 1분 전 한낮빛(100%). 이 동안은 말을 걸지 않는다. 끝나면 “잘 쉬셨어요?”라고 알린 뒤 등받이를 세우고 창문을 연다. 다시 출발할 때 “아직 멍하면 차 밖에서 1분만 걸어 보세요”라고 덧붙인다.
- 밝기·온도·시점은 기획 초기값. 원래 밝기·온도는 휴식을 시작할 때 기억해 두었다가 재출발 때 되돌린다.
- 시연 영상: [`docs/demo/shimpyo_nap_capsule.mp4`](docs/demo/shimpyo_nap_capsule.mp4)(낮잠 캡슐), [`docs/demo/shimpyo_talk_games.mp4`](docs/demo/shimpyo_talk_games.mp4)(같이하기 말놀이). Pleos Connect Emulator 2.1.0에서 녹화. 에뮬레이터 소리가 PC로 나오지 않아, 앱 기록의 시각에 맞춰 화면 문장을 윈도우 한국어 음성으로 입혔다(실차에서는 Pleos Gleo 음성). 대답은 시연용 자동 입력.

### 졸음 판단 근거 (`core/RiskEngine.kt`)
| 신호 | 어떻게 얻나 | 근거 | 점수 |
|---|---|---|---|
| 지난 24시간 수면 | 출발 전 “몇 시간 주무셨어요?” | Tefft(2016, AAA 교통안전재단): 7시간 이상 대비 사고율 6~7h 1.3배, 5~6h 1.9배, 4~5h 4.3배, 4h 미만 11.5배 / 2시간 이하는 운전 부적합(Czeisler 외 2016 전문가 합의) | 5·12·25·40점(2h 이하 45점), 4h 미만은 처음부터 ‘경고’, 2h 이하는 ‘휴식 권고’ |
| 깨어 있은 시간 | “몇 시쯤 일어나셨어요?” + 경과 시간 | Williamson & Feyer(2000): 17~19시간 깨어 있으면 일부 검사에서 혈중알코올 0.05%와 같거나 나쁨, 더 길면 0.1% 수준 | 17h+ 15점, 24h+ 30점 |
| 졸림 자가평가 KSS(1~9) | 출발 전 + 주행 중 30~60분마다 | Åkerstedt 외(2014, J Sleep Res 23:240): KSS 7 이상은 운전 수행 저하와 특히 관련, 객관 지표만큼 민감·타당 | 7=20점(최소 ‘주의’), 8=35점(최소 ‘경고’), 9=50점(‘휴식 권고’) |
| 연속 주행 | 차량 주행 시간 | 도로공사 “2시간마다 휴식” 권고 | 40분 10점, 60분 20점, 90분 35점, 120분 50점 |
| 시간대 | 시계 | 졸음 관련 사고는 새벽 2~6시에 가장 많고 오후 2~4시에 한 번 더 는다(Horne & Reyner 1995, BMJ 310:565) | 2~5시 20점, 0~1시·6시 15점, 14~15시·22~23시 10점, 13시·16시 5점 |
| 대답 속도 | 말놀이 대답까지 걸린 시간을 ‘오늘의 나’와 비교 | 수면이 부족하면 반응이 느려진다(Williamson & Feyer 2000의 반응 속도 검사). 음성 대답 지연을 졸음 지표로 쓰는 것은 쉼표의 가설이라 단독으로 쓰지 않는다. 대답이 두 개 이상 모였을 때만 비교한다(한 번 느린 것은 무시) | 1.5배 15점, 2배 30점 |
| 무응답 | 질문에 대답이 없음(마이크·인식이 없을 때는 세지 않음) | 한 번은 못 들었거나 다른 데 집중했을 수 있어 약하게, 연달아 대답이 없으면 강하게 본다 | 1번 15점, 2번 연속 35점 |
| 정답률 | 계산·구구단·숫자 거꾸로 등 최근 5문제 | 수면 부족 시 정확도 저하(Williamson & Feyer 2000) | 8~15점 |

> 이 앱은 **의료기기가 아니며 졸음을 진단하지 않는다.** 수면·KSS 구간은 위 연구를 따랐지만 점수로 바꾸는 가중치는 초기값이고, 실제 주행 데이터로 조정해야 한다.
> 대답을 못 알아들은 항목은 비워 두고 다른 신호로만 판단한다. KSS는 직전 몇 분의 상태라 30분이 지나면 다시 묻는다.
> 쉬고 온 뒤 45분 동안은 쉼터를 다시 권하지 않는다(수면 부족처럼 쉬어도 바로 사라지지 않는 신호 때문에 쉬자마자 또 권하는 것을 막기 위함). 단, KSS 9(잠과 싸우는 중)라고 답하면 바로 권한다.
> Tefft(2016)는 수면 시간을 운전자가 스스로 답한 자료이고, 자정~오전 6시 사고가 빠져 있어 새벽 위험은 오히려 덜 반영됐을 수 있다.

### 차량 특화 놀이 (구현됨) — 차 안에서만 할 수 있는 놀이
말놀이 8가지가 기본으로 돌고, **세 번에 한 번(1·4·7번째)** 은 Pleos 내비 현재 위치와 진행 방향, 졸음쉼터 공공데이터로 만든 놀이를 낸다.

| 놀이 | 예시 | 쓰는 것 |
|---|---|---|
| 지역 O/X | “칠곡 졸음쉼터는 경상북도에 있다.” “○○ 졸음쉼터에는 차를 10대보다 많이 세울 수 있다.” | NaviHelper 현재 위치 → 가장 가까운 쉼터 3곳의 시도·시군구·노선·주차면수 |
| 쉼터 거리 맞히기 | “앞쪽 오창 졸음쉼터까지 직선거리로 몇 킬로미터쯤 될까요?” → “거의 맞혔어요. 약 8킬로미터예요. 피곤하면 들렀다 가요.” | 현재 위치·진행 방향 → 앞쪽 쉼터 2곳까지 직선거리(오차 20% 또는 2km 안이면 정답) |

- 정답은 모두 데이터에서 바로 나온다. 지역 특산물·역사처럼 데이터에 없는 내용은 확인 없이 지어낼 수 있어서 넣지 않았다.
- 졸음쉼터는 상·하행에 같은 이름으로 한 쌍씩 있고 둘의 값이 다를 수 있다(예: 상번천 주차 34면·7면, 삼례 완주군·익산시). 그래서 **같은 이름 전체에서 답이 하나로 모이는 문제만** 낸다. 실제 데이터 253곳 전체로 문제를 만들어 이 조건을 검사하는 단위 테스트가 있다.
- 거리 맞히기는 진행 방향을 알 때만 낸다(‘앞쪽’ 쉼터를 골라야 하므로).
- 원본 데이터의 노선 이름 중 `광주광역시대구선`, `대전라남도부순환선`처럼 지명이 잘못 바뀐 듯한 값은 문제에 쓰지 않는다(깨끗한 고속도로 14개만). 화장실 여부는 253곳 모두 ‘있음’이라 문제로 쓰지 않는다.
- 이 놀이들은 그 지역을 아는지에 따라 정답률이 달라져서 **졸음 판단의 정답률에는 넣지 않고**(대답 속도는 그대로 잰다), 경고 단계에서는 정답률을 재는 집중 놀이를 우선한다.
- 거리 맞히기는 정답을 듣는 것만으로 ‘쉴 곳이 얼마나 가까운지’를 운전자가 알게 되는 장치이기도 하다.

### 동승자가 있을 때: 수면 점검은 그대로, 놀이는 같이하기 또는 조용히 (구현됨)
수면 시간은 졸음 판단에서 가장 중요한 정보라, **동승자가 있어도 출발 전 세 질문(10초 남짓)은 그대로 묻는다.** 3시간 자고 출발한 사람을 놓치지 않기 위해서다. 그다음 놀이 방식을 정한다.

| 기본값(설정, 주차 중에만 변경) | 동승자가 타면 |
|---|---|
| 물어보기(기본) | “동승자분도 같이 말놀이 하실래요?” → ‘같이 할게’면 같이하기, ‘혼자 할게’면 조용한 감시 |
| 항상 같이 | 규칙을 안내하고 바로 같이하기 |
| 항상 혼자 | 조용한 감시 |

- **주행 중에도 말로 바로 바꾼다**: 쉼표가 질문하고 듣는 중에 “같이 할게”, “혼자 할게”라고 하면 된다(늘 듣고 있는 것은 아니다. 수면 점검·졸림 질문의 대답에서는 읽지 않는다).
- “같이 하실래요?”에 대답이 없거나 알아듣지 못하면 대화를 방해하지 않는 쪽(조용한 감시)으로 간다.
- 잠을 거의 못 자 처음부터 경고 단계면, 같이하기 질문보다 쉼터 제안을 먼저 한다. 착좌 센서가 없는 차에서도 이 말로 같이하기를 켤 수 있어서, 센서 지원 여부에 덜 좌우된다.
- 설정은 운전 중 화면 조작을 막기 위해 **주차(P단) 중에만** 바뀐다. 앱을 다시 켜도 남는다.

**같이하기(팀 게임)**
- 쉼표가 매번 “운전자분 차례예요.”, “동승자분 차례예요.”라고 차례를 불러 준다. 같이하기에선 둘이 두 번씩 답하도록 한 판을 한 차례 늘린다.
- **졸음 판단에는 운전자 차례 대답만** 쓴다(대답 속도·정답률). 동승자 차례 대답은 팀 점수에만 쓴다.
- 마이크 하나로는 누가 말했는지 확실히 가를 수 없으므로, 같이하기 중에는 **대화 신호(대답 속도·정답률)를 절반**, **운행·수면 신호(연속 주행·시간대·수면·깨어 있은 시간)를 1.2배**로 반영한다(기획 초기값). KSS는 “운전자분께 여쭤볼게요.”로 운전자에게만 묻는다.
- 동승자는 말 대신 **화면 패드(O/X·숫자·패스)** 로 답할 수 있다. **운전자 차례에 동승자가 화면으로 답하면 반칙**: 그 대답은 쓰지 않고 팀 점수 1점을 빼며 쉼표가 알려 준다. 말로 끼어드는 것은 마이크로 가를 수 없어 규칙 안내(“남의 차례에 대답하면 반칙이에요”)로 막는다.
- 팀 점수 = 맞힌 수 − 반칙. 화면 세 번째 칸에 보인다.

**조용한 감시(동승자 있음 + 혼자)**

| | 혼자 운전 | 동승자 있음 + 혼자 |
|---|---|---|
| 출발 전 | 수면 점검 3문항 | 수면 점검 3문항(“운전자분께 여쭤볼게요.”) + 같이하기 여부 |
| 주의(30점~) | 외기 유입 → 말놀이, KSS 질문 | **아무것도 하지 않음.** 연속 주행 시간·시간대·수면 신호만 계산 |
| 경고(50점~) | 쉼터 제안 | “바깥 공기를 조금 넣을게요.” → 외기 유입 → “운전하신 지 2시간 됐어요. ○○ 졸음쉼터에서 15분 쉬었다 갈까요?” (‘졸려 보인다’ 대신 사실만) |
| 거절하면 | 대화를 더 자주 + 10분 뒤 다시 | 10분 뒤 다시 묻기만 |

**동승자 신호**
- `Seat.registerSeatOccupancy(SeatArea, SeatOccupancyListener)`로 운전석(ROW_1_LEFT)을 뺀 모든 좌석을 구독한다. 한 자리라도 사람이 있으면 동승자 있음.
- 착좌 센서를 읽을 수 없는 차는 `Safety.registerSeatBeltNotBuckledWarning`을 보조로 쓴다. 이 경고는 ‘사람이 앉았는데 벨트를 안 맸을 때’만 켜지므로, 한 번 켜진 것을 보면 동승자가 있다고 보고 **주차할 때까지** 기억한다.
- 신호가 없거나 불확실하면(null) 동승자 없음으로 본다. 졸음 개입이 꺼지는 쪽으로 틀리지 않게 하기 위해서다.
- **SDK 진단 탭의 `[Seat 착좌]`, `[Safety 벨트]`, `[동승자] 신호: … · 지금: …` 줄**에서 이 차(에뮬레이터)가 어떤 신호를 주는지 바로 확인할 수 있다.
- 좌석별 목소리 구분(다중 마이크): 공개된 Pleos SpeechToText API(initialize·registerApp·addListener·request·stop·sendAudio·completeAudioSend)에는 좌석이나 화자를 지정·구분하는 항목이 없다. 그래서 지금은 ‘차례 부르기 + 운전자 차례만 반영 + 반칙 규칙’으로 풀었고, 좌석별 음성 구간 정보가 SDK로 열리면 운전자 목소리만 골라 쓰는 쪽으로 넓힌다(확장 포인트).

### 무입력 출발(웨어러블·캘린더) — 인터페이스와 시연용 구현까지, 실제 연동은 확장 단계
매번 출발 전에 질문에 답하는 것도 부담이다. 그래서 출발 전 정보를 `PreDriveSource` 인터페이스로 분리해 두었다.

- **수면 기록이 있으면** 수면 시간·기상 시각 질문을 건너뛰고 그 값으로 그날의 위험도 기준을 바로 잡는다.
  (“갤럭시 워치 기록으로 지난밤 5시간 30분 주무신 걸 확인했어요.”) 졸린 정도(KSS)는 ‘지금’의 상태라 웨어러블로 알 수 없어서, 주의 단계가 되면 평소처럼 한 번 묻는다.
- **수면 기록에 맞춰 출발 실내를 미리 바꿔 둔다**(`core/SleepPrep.kt`). 졸음이 오기 전에, 먼저 한 문장으로 알린 뒤 바꾼다.

  | 워치 기록 | 실내 | 첫 휴식 |
  |---|---|---|
  | 7시간 이상, 깨어 있은 지 17시간 미만 | 그대로 | 평소 |
  | 5~7시간 | 실내 온도 22도 | 평소 |
  | 5시간 미만 또는 깨어 있은 지 17시간 이상 | 외기 유입·송풍 + 실내 온도 21도 | 60분(캘린더 일정이 더 이르면 그쪽) |

  구간은 위험도 계산과 같은 근거(Tefft 2016, Williamson & Feyer 2000)이고 온도 값은 기획 초기값이다. 바꾼 온도는 휴식을 시작하기 전과 운행을 마칠 때 원래대로 돌린다.
- **캘린더에 장거리·심야 일정이 있으면** 출발 인사에서 첫 휴식 시점을 먼저 정해 두고(예상 운전 시간이 길면 110분, 심야면 90분 — 기획 초기값), 그 시점이 되면 위험 점수와 관계없이 “계획한 휴식 시간이에요.”로 권한다. 한 운행에 한 번만 이렇게 권하고, 그 뒤는 위험도로 판단한다.
- 지금 앱에 있는 것은 **시연용 구현**(`SimPreDriveSource`, 시연 도구의 ‘워치 수면 기록’·‘캘린더 장거리 일정’)뿐이다. 실제 헬스 앱·캘린더와는 연결되어 있지 않다.
- 실제 연동 구상: 수면 기록은 스마트폰에 있으므로(삼성 헬스·갤럭시 워치 → Health Connect, 애플 워치 → iPhone의 HealthKit) 스마트폰 동반 앱이 운전자 동의를 받아 지난밤 기록과 오늘 일정만 차로 넘기는 구조. 애플 건강 데이터는 iPhone에서만 읽을 수 있어 iOS 앱이 따로 필요하다.
- 알아 둘 점: 수면 질문을 건너뛰면 출발 직후에 대답 속도 기준값이 잡히지 않고 첫 말놀이에서 잡힌다. 그래서 무입력 출발에서는 대답 속도보다 수면·주행 시간 신호의 비중이 커진다.

### 쉼터 미니맵 (구현됨)
- 쉼터를 권할 때와 경유지로 가는 동안 왼쪽 계기 자리가 **미니맵**으로 바뀐다. 머리글의 **지도 보기 / 계기 보기**로 언제든 바꿀 수 있다.
- 졸음쉼터 공공데이터 253곳을 점으로 찍고(점이 모이면 고속도로망 모양이 된다), 내 위치(진행 방향 화살표), 앞쪽 쉼터 이름, 지금 권하는 쉼터나 경유지(휴식 색 파랑, 점선, 거리)를 얹는다.
- 바탕 지도(도로·지명)가 없는 개요도다. 대신 **지도 API 키도 인터넷도 필요 없어서** 시뮬레이터·Pleos 에뮬레이터·실차 어디서나 똑같이 나온다.
- **바탕 지도(`ui/MapTiles.kt`)**: 인터넷이 있으면 미니맵 맨 아래에 지도 타일(도로·지명)을 깔고 그 위에 쉼터·내 위치·권하는 쉼터를 그대로 그린다. 출처는 지도 오른쪽 위에 표시한다.
  1. **구글 지도** — `local.properties`에 `MAPS_API_KEY`(Google **Map Tiles API**가 켜진 키)가 있을 때. 세션을 만들어 2D 타일을 받는다.
  2. **오픈스트리트맵** — 키가 없거나 구글이 거절했을 때(키 필요 없음).
  3. **개요도** — 인터넷이 없을 때(지금까지의 미니맵).
  - Pleos Connect에는 구글 플레이 서비스가 없어 Maps SDK for Android를 쓸 수 없고, WebView(Maps JavaScript API)는 이 화면의 시트 흐림·전환 레이어 안에서 그려지지 않았다. 그래서 타일을 직접 받아 Canvas에 그린다.
  - Pleos 화면 톤에 맞춰 채도를 낮췄고(다크 모드는 반전), 전국 보기처럼 너무 넓을 때는 타일을 쓰지 않는다.
  - **쉼터까지 도로 경로(`ui/RoadRoute.kt`)**: 쉼터를 권하거나 경유지로 가는 동안 내 위치→쉼터의 실제 도로 경로를 선으로 그리고, 이름표에 도로 거리·예상 시간을 적는다. 구글 Routes API는 한국 안 자동차 경로를 주지 않아(빈 응답, 국내 지도 데이터 반출 제한) 오픈스트리트맵 데이터로 길을 찾는 OSRM 공개 서버를 쓴다(키 필요 없음). 실패하면 직선 점선. 길안내 자체는 Pleos 순정 내비가 맡는다.
  - 에뮬레이터의 순정 내비 화면은 바탕 지도가 비어 있다(에뮬레이터에 내비 지도 데이터가 없는 것으로 보임). 시스템 앱이라 쉼표가 바꿀 수 없다.
  - 오픈스트리트맵 공개 타일 서버는 적은 사용량(시연·시제품)을 전제로 한다. 양산 때는 구글 키나 상용 타일 서비스를 쓴다.
- 길안내는 하지 않는다. Pleos는 ‘경로 하나 · 내비 하나’ 원칙이라 길안내는 순정 내비의 몫이고, 쉼표는 경유지만 넣는다.
- 누르면 내 주변 ↔ 전국 보기가 바뀐다. 위치를 아직 못 받았거나 국내가 아니면(예: 일반 에뮬레이터 기본 위치) 전국 보기로 나온다.
- 앞쪽 쉼터에는 거리를 적지 않는다(‘쉼터 거리 맞히기’ 답이 되므로). 거리는 권하는 쉼터·경유지에만 적는다.
- 영역·축척·좌표 계산은 `core/MiniMap.kt`(단위 테스트), 그리기는 `ui/ShelterMap.kt`.

### 안전 원칙 (코드에 그대로 구현)
- 등받이 눕히기·창문 열기는 **주차(P단)가 확인될 때만** 한다. 등받이 세우기·창문 닫기는 언제든 한다(누운 채 운전하는 것이 더 위험하다). 휴식 중 출발이 감지되면 먼저 알리고 등받이를 바로 세운 뒤 공조·조명을 되돌린다.
- 주차는 **P단**으로 판단한다. D단에서 주차 브레이크만 건 상태(신호 대기·정체)는 주차가 아니다. 기어 신호가 없는 차에서만 주차 브레이크로 대신한다(`core/ParkingSignal.kt`).
- 쉼터로 가는 중에 쉼터(0.6km 안)가 아닌 곳에서 주차하면 휴식을 바로 시작하지 않고 “여기서 15분 쉬어 갈까요?”라고 묻는다.
- 차량을 움직이기 전에 **먼저 음성으로 알린다.**
- 주행 중 화면 조작을 요구하지 않는다. 확인은 모두 음성.
- 차종마다 지원 기능이 다르므로 **capability를 먼저 확인**하고, 범위를 모르면 값을 추측하지 않는다. 지원하지 않는 제어는 음성 안내로 대신한다.
- 마이크·음성 인식이 없을 때의 침묵은 졸음 신호로 세지 않는다.
- 동승자 신호가 불확실하면 평소 모드로 동작한다. 조용한 감시 모드에서도 외기를 넣기 전에 한 문장으로 알린다.
- 대화 내용은 저장하지 않는다. 위험도 계산에는 응답 지연 수치만 쓴다.

## 2-1. 화면 디자인

- **한 화면에 한 가지 이야기.** 왼쪽 계기는 운행 중엔 졸음 위험(0~100), 휴식이 시작되면 같은 자리에서 남은 시간으로 바뀐다. 쉼터를 권하거나 쉼터로 가는 동안에는 같은 자리가 쉼터 미니맵이 된다. 오른쪽은 쉼표가 지금 하는 일을 한 문장으로 말한다.
- **면 대신 선.** 카드·아이콘·칩을 걷어내고 가는 눈금, 2dp 트랙, 6dp 진행 호, 2dp 구분선과 글자 굵기 차이(Asta Sans 300·400·700)로만 위계를 만든다.
- **색은 두 가지 의미에만.** 위험 단계(정상 무채색 → 주의 노랑 → 경고 주황 → 휴식 권고 빨강)와 휴식(파랑). 색 옆에는 항상 글자를 둔다.
- **버튼은 운전석 쪽(왼쪽 아래)에.** 주 행동 하나만 채운 알약형(높이 100dp), 나머지는 선이나 글자만.
- **시연·진단 조작은 분리.** 오른쪽 위 ‘시연 도구’를 누르면 패널이 열린다. 운전 화면에는 운전자에게 필요한 것만 남겼다.
- **Pleos 규격 유지:** Asta Sans, Pleos 색 토큰(라이트·다크), 최소 터치 48dp, Large 버튼 높이 100, 칩은 Small 버튼 높이 64, 그림자 L3(패널), 공식 로딩 모션. 차량의 라이트/다크 설정을 따른다.
- **Pleos와 다르게 한 점:** 가이드의 제목은 Bold·ExtraBold지만, 고급스러운 인상을 위해 큰 숫자와 제목만 Light(300)를 썼다. 크기·행높이·대비(4.5:1 이상)는 지켰다. 심사 기준이 엄격하면 `ShimpyoType`에서 굵기만 바꾸면 된다.
- **주행 중 장식 모션 없음.** 움직이는 것은 ‘듣고 있어요’ 로딩, 값이 바뀔 때의 계기 호와 미니맵(내 위치·영역), 사용자가 연 패널뿐이다.
- **모션은 스프링으로.** 시간 대신 스프링(SwiftUI처럼 response·damping으로 설정, 기본 response 0.5s)으로 움직여서, 손을 뗀 순간의 속도를 이어받아 멈춘다. 값은 `ui/theme/Motion.kt` 한 곳에 있다.
  - 문장·제목·버튼 묶음 교체: 이전 것은 흐려지며 위로, 새것은 흐릿하게 올라오며 선명해진다(blur replace).
  - 숫자: 자리마다 굴러간다. 커지면 아래에서, 작아지면 위에서 들어오고 바뀌지 않은 자리는 그대로다.
  - 계기: 위험 계기(270°)가 휴식 시계(360°)로 끊김 없이 펼쳐지고, 색도 같은 스프링으로 바뀐다.
  - 단계 점: 선을 따라 미끄러지고, 지나간 점은 빈 고리에서 작은 점으로 차오른다.
  - 시연 도구: iOS 카드 시트처럼 뒤 화면이 95%로 작아지고 흐려지며 물러난다. 끌어서 닫을 수 있고, 너무 당기면 고무줄처럼 버틴다. 뒤로 가기로도 닫힌다.
  - 누름: 버튼·칩이 96%로 눌렸다 돌아오고, 스위치 손잡이는 누르는 동안 옆으로 늘어난다. 밑줄 탭은 밑줄이 미끄러진다.
  - 첫 실행 한 번만: 눈금이 시계 방향으로 켜지고 제목→문장→단계→수치가 차례로 올라온다.
  - 주차 후 휴식 중에만: 4초 들이쉬고 6초 내쉬는 호흡 빛. **주행 중 반복 모션은 없다.**
  - 시스템 ‘애니메이션 삭제’가 켜져 있으면 모든 전환이 즉시 바뀐다.
- **가독성 보완(2026-11-10):**
  - 쉼표가 한 말은 자르지 않는다(최대 5줄). 길면 32 → 28 → 26sp로 줄인다(무입력 출발 인사가 130자 남짓).
  - 한국어는 띄어쓰기 단위로 줄바꿈한다(`LineBreak.WordBreak.Phrase`, API 33+).
  - 라이트 테마의 주의·경고 계기 색은 대비 3:1 이상이 되도록 진한 노랑·주황을 쓴다.
  - 머리글은 상태(흐린 글자)와 누를 수 있는 것(지도 보기·시연 도구, 구분선 오른쪽)을 나눴다.
  - '휴식 취소'는 쉼터로 가는 중일 때만 보인다.
  - 동승자 패드는 답 버튼 줄과 숫자 키 줄로 나눠 늘 같은 자리에 둔다.
- 1280dp 이상은 좌우 배치, 반 화면(내비와 분할)·세로 화면은 위아래로 쌓되 운전 중 버튼은 아래에 고정하고 계기·문장만 스크롤한다. 동승자 패드가 뜨면 계기를 줄인다. 시안은 `docs/design/`에 있다(`motion.html`은 브라우저에서 자동 재생되는 모션 프로토타입, `motion.mp4`는 그 녹화본).

## 3. 빌드와 실행

### 준비물
- Android Studio 최신 버전, JDK 17
- Pleos Connect Emulator 2.1.0 (Android API 34 시스템 이미지)

### Pleos Connect Emulator 설치 (공식 문서 요약)
문서: https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator

1. Android Studio → **Tools > SDK Manager** → **SDK Update Sites** 탭 → **+**
   - Name: `Pleos Connect System Image`
   - Mac: `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-arm64-sys-img.xml`
   - Windows/Linux: `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
2. **SDK Platforms** 탭에서 Android API Level 34의 Pleos Connect system image를 체크하고 설치 후 Android Studio 재시작
   (이전 버전 에뮬레이터가 있으면 먼저 삭제)
3. **Tools > Device Manager** → Form Factor `Automotive` → 기기 `Pleos Connect v2.1.0`
   → System image `Pleos Connect v2.1.0 APIs`(API 34) → RAM 4GB, Default boot `Cold`

### 실행
1. Android Studio에서 이 폴더(`Shimpyo`)를 연다. Gradle Sync 때 Pleos SDK가
   `https://nexus-playground.pleos.ai/repository/maven-releases/`에서 자동으로 내려받아진다.
2. Pleos Connect AVD를 켜고 **Run ▶**
3. 처음 실행 때 마이크 권한을 허용한다.

명령줄: `./gradlew installDebug` · 단위 테스트: `./gradlew testDebugUnitTest`

### 마이크로 대답하기 (에뮬레이터)
에뮬레이터는 기본으로 PC 마이크 입력을 막는다. 아래 스크립트로 켜면 `-allow-host-audio`가 붙어 PC 마이크가 열린다.
```bash
powershell -ExecutionPolicy Bypass -File tools/start-emulator.ps1
```
윈도우 설정 → 개인 정보 → 마이크에서 ‘데스크톱 앱이 마이크에 액세스’가 켜져 있어야 한다. 노트북 스피커 소리는 마이크의 에코 제거로 지워지므로, 테스트는 사람이 직접 말해야 한다.
Android Studio에서 켰다면 Running Devices ⋮ → Extended Controls → Microphone → **Virtual microphone uses host audio input**을 켠다. 쉼표가 질문을 마치고 ‘듣고 있어요’가 보일 때 말하면 된다.

### 구글 지도 키 (선택)
1. Google Cloud Console에서 프로젝트를 고르고(결제 계정 연결 필요) **Map Tiles API**를 사용 설정한다.
2. 사용자 인증 정보 → API 키를 만들고, API 제한을 Map Tiles API로 건다.
3. 프로젝트 폴더의 `local.properties`(저장소에 올라가지 않음)에 한 줄 넣고 다시 빌드한다. 키가 거절되면 앱은 오픈스트리트맵으로 동작한다.
```
MAPS_API_KEY=발급받은키
```
키는 APK 안에 들어간다. 키를 넣은 APK를 공개 저장소에 올리지 않는다(지금 배포한 APK에는 키가 없다).

### OneDrive 안에서 빌드가 실패할 때
`Failed to delete some children`이 나면 동기화 프로그램이 빌드 파일을 잡고 있는 것이다. 빌드 결과를 동기화 밖에 두면 된다.
```bash
./gradlew -PshimpyoBuildDir=C:/dev/shimpyo-build installDebug
```

### 졸음쉼터 데이터 (포함됨)
`app/src/main/assets/shelters.csv`에 **전국졸음쉼터표준데이터 253곳(2026-02-25 기준)**이 들어 있다.
- 출처: 공공데이터포털(한국도로공사) https://www.data.go.kr/data/15028203/fileData.do · 이용허락범위 제한 없음
- 화면·발표 자료에는 “출처: 공공데이터포털(한국도로공사)”를 적는다.
- 해마다 갱신된다(다음 등록 예정 2027-02-25). 새 CSV를 같은 이름으로 바꿔 넣기만 하면 된다.
  열은 헤더 이름(‘쉼터명’, ‘위도’, ‘경도’ 등)으로 찾으므로 순서는 상관없고, UTF-8이 아니면 EUC-KR로 다시 읽는다.

- 내비 경유지와 음성에서는 “오창 졸음쉼터”처럼 이름 뒤에 ‘졸음쉼터’를 붙여 부른다.
- 파일을 빼면 쉼터 제안 대신 **내비 장소 검색 화면에 ‘졸음쉼터’를 띄우는 방식**으로 동작한다.

## 4. 2차 PT 시연 순서 (약 5분)

오른쪽 위 **시연 도구**를 눌러 패널을 연다.

1. **시연 배속** 켜기(1초 = 주행 1분), 시간대 **새벽 2시** 선택
2. **운행 시작** → 쉼표가 인사하고 수면 점검 세 가지(수면 시간·기상 시각·졸림 정도)를 묻는다. 이 대답으로 응답 속도 기준값도 잡힌다
   (마이크 대신 **수면 점검 대답** 버튼: 짧은 수면을 보여주려면 “세 시간 잤어” → “새벽 네 시” → 졸림 8, 평범한 경우는 “일곱 시간” → 아무 대답 → 졸림 3)
3. 약 40~60초 기다리면 위험도가 ‘주의’로 오르고 쉼표가 외기를 넣은 뒤 말놀이를 시작한다(매번 다른 놀이, 기록 탭에 ‘대화 시작: 초성 퀴즈’처럼 남는다)
   → **느린 대답 3초** 버튼으로 응답이 느려지는 상황을 보여준다
4. 위험도 ‘경고’ → 쉼터 제안 → **“응, 쉬었다 가자”**
   - Pleos 에뮬레이터: 순정 내비에 경유지가 추가된다
   - **가상 주행 → 쉼터 쪽으로 주행**을 먼저 눌러 두면(Pleos 에뮬레이터에서도 됨) 실제 쉼터 이름으로 제안하고, 계기 자리에 미니맵이 떠서 내 위치·권하는 쉼터·거리가 보인다. 차는 1초마다 조금씩 앞으로 움직인다
5. 가상 주행이면 차가 경유지까지 가서 저절로 도착한다(아니면 **가상 주행 → 경유지 도착**) → Virtual Console에서 기어 **P**(또는 시연 패널 **주차**)
   → 등받이·조명·공조가 바뀌는 것을 가상 차량 상태 또는 실제 SDK 기록으로 보여준다
6. 15초(=15분) 뒤 창문 환기 → 20초 뒤 원위치 요청, 쉼표 경유지 정리(이미 도착한 경유지는 삭제하지 않음), 재출발 안내
7. **SDK 진단** 탭에서 실제로 호출한 Pleos API 이름과 각 기능의 지원 여부를 보여준다
8. (동승자) **운행 종료** → 시연 도구 **동승자 (착좌 센서) → 동승자 있음**(Pleos 에뮬레이터면 Virtual Console의 동승석 착좌) → **운행 시작**
   → “동승자분도 계시네요” 인사 뒤 수면 점검 세 가지 → “같이 말놀이 하실래요?”
   - **“혼자 할게”**(운전자 대답 버튼): 화면 제목이 ‘동승자와 함께, 조용히’로 바뀐다. ‘주의’가 돼도 말하지 않다가 ‘경고’가 되는 순간 외기 유입과 함께 쉼터를 한 번만 권한다
   - **“같이 할게”**: 상단에 ‘같이하기’, 세 번째 칸에 ‘팀 점수’. 말놀이마다 “운전자분 차례예요 / 동승자분 차례예요”를 부르고, 동승자 차례에는 화면 패드(O/X·숫자)로 답할 수 있다. 운전자 차례에 패드로 보내면 반칙 안내와 함께 팀 점수 −1
   - 같이하기 기본값은 시연 도구 **같이하기 기본값** 칩에서, **차량 → 주차**일 때만 바뀐다
8-1. (차량 특화 놀이) **가상 주행 → 쉼터 쪽으로 주행**을 먼저 누르고 운행 → 첫 말놀이가 ‘쉼터 거리 맞히기’ 또는 ‘지역 O/X’로 나온다(기록 탭 ‘대화 시작: …’)
9. (무입력 출발) 시각 **오전 10시**, 동승자 **혼자**로 두고 **워치 수면 기록 → 4시간**(또는 5시간 30분·7시간 30분)을 고른 뒤 운행 시작 → 수면 질문 없이 “잠이 많이 부족한 날이라 바깥 공기를 넣고 실내를 21도로…”라고 알리고 공조가 바뀐다(기록 탭 ‘출발 실내 온도 21도: 완료’)
10. (무입력 출발 + 일정) **캘린더 장거리 일정**도 켜고 운행 시작 → 수면 질문 없이 “지난밤 5시간 30분…”과 “1시간 50분쯤 지나면 쉬어 가자”로 시작한다. 세 번째 칸에 ‘계획한 휴식까지 ○분’이 줄어든다

| Sync 때 `Could not move temporary workspace … AccessDeniedException` | 백신(AhnLab V3 등)이 Gradle이 막 만든 파일을 잡고 있음 | 백신 **자체 설정**의 검사 예외에 `C:\Users\<사용자>\.gradle`과 프로젝트 폴더 추가. 안 되면 첫 Sync 동안만 실시간 검사·랜섬웨어 보호를 끄고, `.gradle\caches` 삭제 후 다시 Sync |
| `Gradle 8.11.1 is incompatible with the Gradle JVM version 25` | Android Studio 기본 Java가 25 | 창에서 **Use JVM 21** |
| 앱은 뜨는데 SDK 진단이 "시뮬레이터" | AVD 이름만 Pleos이고 시스템 이미지는 일반 Android 15(API 35) | Device Manager → Edit → **API 34 + "Pleos Connect v2.1.0 APIs"** 이미지 선택 |
| 프로젝트가 이상하게 열림(`.gradle`, `Shimpyo_PitStop_app`이 최상위) | 폴더를 잘못 고름 | `build.gradle.kts`가 들어 있는 **`shimpyo` 폴더**를 한 번 클릭하고 Select Folder |
| 안내 음성 첫 음절이 살짝 깨짐 | Pleos TTS 서비스가 100ms 무음만 채우고 재생을 시작하는데 첫 음성이 그보다 조금 늦게 와서, 출력이 잠들어 있던 상태면 앞부분이 끊김 | 앱이 2초 넘게 조용했으면 말하기 직전에 0.4초 무음을 먼저 틀어 출력을 깨운다(`OutputWarmer`). 비교하려면 `adb shell setprop debug.shimpyo.warmup 0`(끄기) / `1`(켜기) |
| 공조 제어가 `areaId is Invalid`로 실패 | 공조 영역은 ‘1열 전체’처럼 묶여 있는데 운전석 하나로 만든 영역을 넣음 | capability가 알려 준 영역을 그대로 쓰도록 수정 |
| 휴식 뒤 온도·송풍이 원래대로 안 돌아옴 | SDK 2.3.2의 공조 읽기 메서드는 `getHvacTemperature`(‘getCurrent’가 아님)라 원래 값을 저장하지 못함 | `getCurrent…` → `get…` → `get…State` 순서로 찾도록 수정. 읽기 실패는 기록 탭에 남김 |
| 등받이가 ‘현재 위치를 읽지 못함’ | `SeatArea(vararg SeatValue)`를 빈 영역으로 만들어 넣음 | 가변 인자에 운전석 값을 담아 만들도록 수정 |
| 등받이 ‘멈춤’이 ‘뒤로’로 바뀔 위험 | `moveSeatBackrestAngle`은 숫자가 아니라 `MoveControl`(BACKWARD·STOP·FORWARD)을 받는데 0을 이름으로 못 맞춰 첫 값(BACKWARD)이 들어감 | 숫자 부호로 BACKWARD·STOP·FORWARD를 고르고, 못 고르면 실패시키도록 수정. 이미 충분히 젖혀져 있으면 세우지 않음 |
| 공조가 꺼져 있으면 송풍·온도가 거절됨 | 공조 전원이 꺼진 상태 | 외기·휴식 공조·출발 온도가 필요할 때 공조를 켜고, 마지막 기능이 끝나면 원래(꺼짐)로 되돌림. 현장 디버깅은 `adb logcat -s ShimpyoLog` |
| 음성 인식이 안 됨 | 에뮬레이터가 PC 마이크를 쓰지 않음 | `emulator -avd … -allow-host-audio`로 켜거나 Running Devices ⋮ → Extended Controls → Microphone → **Virtual microphone uses host audio input** 켜기 |
| 시연 중 차량 설정·내비 화면이 저절로 앞으로 나옴 | 에뮬레이터 왼쪽 화면(`ai.umos.drivingview`)이 차량 설정 앱을 띄움. 쉼표가 뒤로 가면 안드로이드가 앱을 잠시 멈춘다 | 하단 쉼표 아이콘으로 다시 앞으로. 녹화 중이면 `adb shell am start -n com.pitstop.shimpyo/.MainActivity` |
| 화면 녹화(`adb shell screenrecord`)에 소리가 없음 | 안드로이드 화면 녹화는 소리를 담지 않고, 이 에뮬레이터는 소리가 PC 출력으로도 나오지 않았음 | 앱 기록(`adb logcat -v epoch -s ShimpyoLog`)의 시각에 맞춰 음성을 따로 입힌다(docs/demo 영상이 이 방식) |
| AGP·Kotlin 업그레이드 알림 | — | 지금은 **업그레이드하지 않기** (버전을 바꾸면 다른 곳이 깨질 수 있음) |

OneDrive 안(바탕화면 등)이나 한글이 들어간 경로보다 `C:\dev\` 같은 짧은 경로에 두는 게 안전하다. Android Studio는 관리자 권한 없이 실행한다.

## 6. 알려진 한계와 다음 단계
- **대화는 규칙 기반**(말놀이 8종·짧은 질문)이다. 퀴즈 정답은 계산하거나 직접 검토한 문장만 쓴다. 네트워크 없이도 동작하고 틀린 사실을 말하지 않게 하기 위해서다.
  Gleo AI **LLM SDK**는 서버 등록(clientId/secret)이 필요해 다음 단계에서 붙인다(`TalkGame` 인터페이스로 교체 가능).
- **분기·회전 직전 대화 멈춤**(NaviHelper TBT 정보 활용)은 기획에 있으나 아직 구현하지 않았다.
- 응답 지연·정답률은 그 자체로 검증된 졸음 측정법이 아니다. 단독으로 쓰지 않고 수면·KSS·주행 시간과 함께 판단한다.
  가중치(`RiskEngine`)는 초기값이며 실제 주행 데이터로 조정이 필요하다.
- 웨어러블·캘린더 연동은 인터페이스(`PreDriveSource`)까지만 있다. 스마트폰 동반 앱(Health Connect / HealthKit·캘린더 읽기, 운전자 동의, 차량 전송)이 다음 단계다.
- 착좌 센서가 없는 차에서 안전벨트 경고만으로는 ‘벨트를 맨 동승자’를 처음부터 알 수 없다. 경고를 한 번 봐야 조용한 모드로 바뀐다.
- 차량 주행 시간은 값의 증가량으로 분·초를 추정하며, 확인 전에는 앱 시계를 쓴다. 장시간 정차와 짧은 이동이 섞이는 경우의 단위 추정 정확도는 실차 확인이 필요하다.
- 차량 제어 권한은 출시 때 Pleos App Market과 사전 협의·승인을 받아야 한다.
- 운행 중 포그라운드 서비스로 앱을 유지한다. Android의 백그라운드 시작 제한·차량 서비스 단절·프로세스 종료 뒤의 실제 동작은 별도 확인이 필요하다.
