## 수정 내용과 근거

### 1. 주차 신호를 잃어도 휴식·깨우기를 계속하던 문제

AAOS 오류 콜백을 무시해 이전 P단 값이 남았고, 컨트롤러도 `false`일 때만 출발 처리했다. 이제 상태가 사용 불가·오류이면 값을 비우고, 기어 속성이 있는 차에서는 신호 소실을 주차 브레이크로 대신하지 않는다. 휴식·깨우기 중 `null`도 휴식 중단과 차량 복귀 사유다. 실제 출발을 확인한 것은 아니므로 안내도 ‘주차 상태를 확인할 수 없음’으로 구분한다.

### 2. 제어 완료 응답 전 또는 일부 이동 뒤 실패한 시트 복귀 누락

기존 코드는 눕히기 완료 응답이 와야 시트가 움직였다고 보았다. 응답 전에 실제 시트가 움직이거나 일부 이동 후 FAILED가 오면 복귀를 빠뜨렸다. 이제 요청 시점부터 복귀 필요 상태를 보수적으로 기록하고, UNSUPPORTED와 FAILED를 구분한다. 늦은 실패 뒤 이미 주행 중이면 ‘직접 눕혀 주세요’라고 말하지 않는다. 창문도 같은 원칙을 적용했다.

위 두 문제의 세 가지 컨트롤러 시나리오는 원본 클래스를 대상으로 별도 컴파일한 동일 테스트에서 실패를 재현했다. 수정본에서는 통과했다. 로그: `verification/logs/03-regression-before.log`.

### 3. 시트 이동 중 시간 초과·취소·정지 실패

기존 이동 코드는 전체 시간 초과 때 모터 정지를 요청하지 않았고, 뒤늦은 capability·위치 응답이 이동을 시작할 수 있었다. 목표에 못 닿아도 조금 움직이면 DONE으로 처리했으며, 복귀 요청 시 원래 위치를 먼저 지웠다.

실제 메서드 탐색은 유지하면서 이동 순서를 `BackrestMotion`으로 분리했다. 시간 초과·취소 시 정지를 요청하고, 끝난 요청의 늦은 콜백은 이동을 재개하지 않는다. 목표 도달과 정지 응답을 모두 확인해야 성공이다. 복귀 실패 때 원래 위치를 보존하며, 운전자가 이미 더 세워 놓았으면 복귀 명목으로 다시 눕히지 않는다. 위치 직접 지정 방식도 원래 위치를 읽지 못하면 눕히지 않는다.

모터 명령이 실제 차량에서 실행·정지됐다는 뜻은 아니다. 가짜 SDK 형태의 객체와 가상 시계로 명령 순서·실패 처리·재시도 상태를 시험했다.

### 4. 위치 직접 지정·공조·조명·창문 복귀 실패 시 원래 값 유실

공통 `restore`도 실제 복귀 성공 전에 저장한 값과 영역을 제거했다. `SavedVehicleValues`로 저장·복귀를 묶어 성공할 때만 제거한다. 실패·응답 누락 후 같은 값과 영역으로 재시도할 수 있고, 늦은 이전 성공 응답이 다음 휴식의 저장값을 지우지 않는다. 원래 값을 모르면서 복귀 완료라고 하지 않는다. 창문은 명시적인 닫힘 대체값(0)을 사용할 수 있다.

### 5. 내비 미연결을 성공으로 꾸미는 문제와 완료 안내

실제 작동판의 가상 내비도 기존에는 경유지 추가 성공을 반환했다. 이제 실제 작동판에서 연결이 없으면 실패로 반환하고, 컨트롤러도 안내를 시작하지 못했다고 말한다. 시연판 가상 내비는 계속 동작한다.

Pleos API 호출 성공은 실제 내비 경로에 반영됐다는 확인과 다르다. 음성·화면을 ‘경유지로 넣었어요’에서 ‘추가 요청’으로 바꿨다. 실제 경유지 반영·도착·목록 순서 변경은 이번에 기기로 확인하지 못했다.

### 6. 웹 동기화와 정리

웹에서도 주차 확인 없이 눕히거나 창문을 열지 않고, 취소 중 기다리던 이전 제어가 새 작업의 상태를 보고 다시 이어지지 않도록 했다. 내비 미연결과 안내 문구도 맞췄다. 웹 실제 함수로 안전 시나리오 6개를 실행하는 `tools/web-safety-test.cjs`를 추가했다.

기존 시트 이동 블록을 시험 가능한 파일로 옮겼고, 더 이상 쓰지 않는 상수·import·옛 주석을 정리했다. 코드가 복잡하다는 이유만으로 안전장치나 미지원 차량의 대체 경로를 삭제하지 않았다. CSV 좌표는 바꾸지 않았으며, 좌표만으로 진입 차로가 보장된다는 문서 표현을 바로잡았다.

## 재현 명령

Android SDK와 JDK 17이 설정된 영문 경로에서 실행한다.

```bash
./gradlew testLiveDebugUnitTest
./gradlew assembleLiveRelease assembleDemoRelease
SHIMPYO_FUZZ_SEEDS=10000 ./gradlew testLiveDebugUnitTest --tests '*ControllerFuzzTest' --rerun
node tools/web-safety-test.cjs
```

퍼즈 기본값은 기존과 같은 600개다. 추가 실행은 `SHIMPYO_FUZZ_START`로 시작 시드를 바꿀 수 있다. 한 시드는 400회의 이벤트·tick을 실행하며, 시드 번호로 재현할 수 있다. 전체 단위 테스트 결과는 `verification/unit-tests`, 실행 로그는 `verification/logs`에 보관한다.

## 확인하지 못한 것과 사용 전 남은 점검

- 이번에는 실차·Pleos Connect 에뮬레이터에서 실행하지 못했다. 연결 기기 조회도 이 환경의 adb 사용자 경로 권한 문제로 완료하지 못했다.
- AAOS 이벤트의 실제 순서·오류 상태·서비스 단절, 기어 미지원 판정, D단+주차 브레이크, 센서가 오류 이벤트 없이 멈추는 경우의 감지 여부.
- 실물 시트의 속도·각도 범위·정지 명령 수용·끼임 방지·현재 위치 읽기·운전자 수동 조작과의 충돌. 시뮬레이터의 ‘3초 안에 시트 복귀’ 검사는 실물 시트가 3초 안에 세워진다는 증거가 아니다.
- 앱 프로세스가 제어 도중 종료되거나 차량 서비스가 끊겼을 때 차량 자체가 안전하게 모터를 멈추는지. 메모리의 원래 위치를 프로세스 재시작 후에도 복구하는 기능은 없다.
- 비동기 공조·창문 명령이 차량 서비스 안에서 뒤섞여 실행되는 경우의 실제 결과와, 모든 복귀 실패 후 재시도의 충분성. 이번 시험은 SDK 서비스 내부의 실행을 재현하지 않는다.
- 내비의 도착 경유지 자동 제거, 운전자가 직접 경유지를 바꿨을 때 FIRST 삭제 대상의 동일성, 실제 반대 차로 진입 방지.
- 주행 시간 단위 추정의 실차 정확도, 백그라운드 자동 시작과 포그라운드 서비스 제한, 사람이 말하는 마이크·TTS 경로.
- 위험도 가중치·대답 지연으로 졸음을 추정하는 효과의 임상·주행 검증은 수행하지 않았다.

따라서 이 결과는 발견한 오류에 대한 코드 수정·자동 검증 결과이며, 무결점 보증이나 실차 사용 안전 승인으로 해석하면 안 된다. 실차 검증 전에는 정지된 시험 환경에서 위 항목부터 확인해야 한다.
